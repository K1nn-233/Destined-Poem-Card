用户没指定语言时，提交信息和 PR 说明一律用中文。读者包括不懂代码的开发组成员，写人话，说清楚改了什么、为什么改、怎么确认没问题。

## 提交前

- 按改动范围跑检查（见 [修改与验证](../../../docs/workflow.md)）：只改世界书正文或数据跑 `pnpm card check`；改代码跑对应包的测试和类型检查；改构建或变量结构跑 `pnpm verify`。没跑的检查不要写成已通过。
- 玩家能感知的改动，在 [CHANGELOG.md](../../../CHANGELOG.md) 的「未发布」下面补一条；需要玩家手动改变量的，条目开头加【不兼容】。
- 不提交：`dist/`、`imports/`、`.cache/`、`node_modules/`、本机酒馆数据、含密钥或个人信息的文件。`git status` 里出现这些就停下来问。
- 不改 `release.json` 的 `version`、`releasedAt`，也不改卡名和世界书名，除非开发组明确说要发布并给了版本号；发版用 `pnpm card release <版本号>`，规则见 [版本、封面与发布](../../../docs/versioning.md)。
- 创建远端、推送、打标签、开 PR 都要用户在当前任务里明确同意。

## 提交信息

```
范围：一句话说清改了什么

- 具体改动一
- 具体改动二
为什么改（一两句，可省略）
验证：跑了哪些检查 / 在酒馆里试了什么；没测的写「未实测」
```

范围从这些里选最贴切的一个：世界书、开局数据、地图、状态栏、自定义开局、自动化、正则、角色卡、工作台、构建工具、文档、发布。标题不超过 50 个字左右，不加句号。例子：

- `世界书：补充帝国精灵的组织设定`
- `地图：新增龙吼堡垒及两条路线`
- `自动化：修复身份字段不显示`
- `发布：V4.3.4`

一个提交只做一件事；顺手改的无关内容拆开提交。

## Pull Request 说明

按 [.github/pull_request_template.md](../../../.github/pull_request_template.md) 填写，标题格式同提交信息标题。

- **开发组自己的 PR**：写清改动、影响（会不会影响旧存档、要不要改变量）、验证情况。改了世界书条目时，列出条目名，方便审阅。
- **外部玩家的 PR**：除上面几项，还要写明内容来源（自己原创、改自谁、是否已获原作者同意），并勾选同意 [LICENSE](../../../LICENSE) 第五节的投稿条款。只说明事实，不替作者做授权声明；不清楚的就留空，让作者自己填。
- 涉及大段设定或 NSFW 内容时，说明里只概括，不贴原文。
